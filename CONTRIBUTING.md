# Как работаем над «ГЛИТЧ-КОРЕ»

Правила для людей и агентов. Раньше они лежали в issue #1 (дорожная карта); теперь живут
здесь и меняются вместе с кодом. Как запускать игру, тесты и релиз — в
[README → «Для разработчиков»](README.md#для-разработчиков).

## Принципы

1. **Каждая задача — issue, каждое решение — PR** с `Closes #N`. Коммиты, описания PR
   и комментарии — на русском.
2. **Только измерения.** «Стало быстрее» или «стало лучше» — не аргумент: в PR нужны
   цифры до и после и команда замера. Баланс — таблица «метрика → цель → факт».
3. **Тесты — часть приёмки.** Новое поведение приходит со сценарием или проверкой
   в автотесте; PR без зелёного CI не сливается.
4. **Решения фиксируются в ADR** (`docs/adr/`). Если поведение — сознательное
   ограничение, оно записывается в ADR, чтобы его потом не «чинили» заново.
5. **Вся графика, звук и анимация — кодом.** Внешних ассетов нет; картинки README и
   иконка пересобираются скриптами из `tools/`.

## Ветки и PR

- Ветка от свежего `main`: `feat/<тема>`, `fix/<тема>`, `docs/<тема>`.
- `main` меняется часто — подтягивайте его посреди работы (`git merge origin/main`),
  а не только перед PR.
- Не коммитьте `project.godot` и `icon.svg.import`, если задача их не меняет: Godot
  переписывает их при каждом запуске.
- В описании PR: что сделано, цифры, какие тесты прогнаны локально, что отложено и
  какие файлы вне своей зоны тронуты.

## Зоны

Параллельная работа идёт по зонам, чтобы PR не конфликтовали. Общие файлы — реестры
сценариев, `README.md`, `Balance` — правятся отдельными блоками в конце, без
переформатирования соседних строк.

| Зона | Файлы |
|---|---|
| Мир, вода, свет, туман | `scripts/autoload/world.gd`, `scripts/world/` |
| Цикл игры, питание, релей | `scripts/autoload/game.gd`, `scripts/machines/machine_base.gd` |
| Машины | `scripts/machines/` |
| Фантомы и угроза | `scripts/entities/phantom.gd`, `scripts/autoload/threat.gd` |
| Игрок и вид героя | `scripts/entities/player.gd`, `scripts/core/avatar.gd` |
| Интерфейс | `scripts/ui/`, `scripts/autoload/ui.gd` |
| Сохранение и профиль | `scripts/core/save.gd`, `scripts/core/profile.gd` |
| Баланс | `scripts/core/balance.gd` (только константы) |
| Сеть | `scripts/autoload/net.gd`, `scripts/net/` |
| Тесты и инструменты | `tools/` |
| Сборка и релиз | `.github/workflows/`, `export_presets.cfg` |

## Тесты

- **Локально — лёгкий прогон:** `--test --seed=31337` и только затронутые сценарии
  (`--scenario=a,b`) на одном сиде; сетевые сценарии — если трогали сеть. Каждый запуск
  Godot — headless и с ограничением времени (`timeout 600`).
- **Полный цикл гоняет CI** на каждом PR: автотест и все сценарии на сидах 31337, 4242,
  12345, сетевые сценарии, экспорт. Падения CI чините по логам
  (`gh run view --log-failed`), а не повторным полным прогоном у себя.
- Сценарии ждут события по `Game.game_time` и `wait_until`, а не по числу кадров:
  на нагруженной машине кадры идут медленнее.
- Тестовые сохранения и профиль изолированы (`scripts/core/test_env.gd`), параллельные
  прогоны не мешают друг другу.

## Сеть

- Хост авторитетен; клиенты шлют только ввод и запросы.
- Любое изменение формата сообщений — это бамп `Net.PROTO` и пересчёт
  `SCHEMA_PROTO`/`SCHEMA_HASH` в `tools/net_test.gd` (он печатает «схема: PROTO N, хэш …»).
  Новые значения `Msg` добавляются только в конец enum. Два PR не должны поднимать PROTO
  одновременно — договоритесь об очереди.

## Вопросы владельцу

Если решение не ваше (дизайн, публикация, ключи), заведите issue с меткой `question`:
варианты, рекомендация и что будет по умолчанию. Работу не останавливайте — делайте
по рекомендации там, где это обратимо.

## Релизы

Только вручную, workflow «Релиз» (`release.yml`): версия, заметки и подписанный APK.
Подробности — в README.
