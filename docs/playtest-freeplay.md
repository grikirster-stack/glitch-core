# Свободная игра до эвакуации

Контрольный забег на сиде `31337` и коммите `7af1c8c`, до реализации [ADR-006](adr/0006-living-base.md). Результат за **5:34 игрового времени**: добыто 33 блока, из них 12 руды, зажжены шесть дуг ядра, уничтожен один фантом, смертей 0. После удержания сигнала открылся экран эвакуации. Это проверка исходного забега. Приёмка строительства после сигнала описана в ADR-006.

## Запуск

Запускайте из корня проекта с Godot 4.7.2. При первом запуске из свежего чекаута импорт зарегистрирует классы GDScript. Вторая команда сразу открывает свободную игру с нужным сидом. Для обычного ввода используйте тестовый профиль или стенд, чтобы автосохранение на рассвете попало в тестовые данные.

```powershell
godot --headless --path . --import
godot --path . -- --seed=31337
```

Для управления агентом запустите [помощник ввода](../tools/playtest_input.gd) в обычном окне. `--headless` годится для импорта, а для кадров нужен рендер. `--test` и `--scenario` меняют условия прогона, в частности поведение директора угрозы в сценариях. `Dummy` отключает вывод звука. Для звуковых предупреждений используйте обычный запуск.

```powershell
$artifactDir = Join-Path ([System.IO.Path]::GetTempPath()) ('glitch-core-playtest-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path $artifactDir | Out-Null
Write-Host $artifactDir
godot --path . --windowed --resolution 1280x720 --audio-driver Dummy --fixed-fps 60 --max-fps 120 --disable-vsync --script res://tools/playtest_input.gd -- "--seed=31337" "--playtest-dir=$artifactDir"
```

Передайте через `--playtest-dir` абсолютный путь к пустой локальной папке. Помощник сохраняет `state.json` и `frame.png` при старте и обновляет их после каждой серии действий. Игра стоит на паузе между сериями, поэтому время на чтение кадра не тратит топливо и не приближает ночь. Тестовая точка входа изолирует игровой профиль и сохранения по процессу.

## Ввод из второго терминала

В `input.json` отправляется объект с целым `id` и массивом `actions`. Первый снимок имеет `id: 0`. Отправляйте строго растущие `id` и дождитесь того же `id` в `state.json`, прежде чем читать новый `frame.png` или посылать следующую серию. Пишите JSON во временный файл в той же папке и затем заменяйте `input.json`. У успешной серии `error` пустой и `png` равен `0`. Некорректное действие возвращает описание в `error` с тем же `id`.

| Действие | Что передать |
|---|---|
| Нажатие или отпускание клавиши | `["key", "E", true]` и `["key", "E", false]`. Используются имена клавиш Godot, например `I`, `Space`, `2`. |
| Курсор по кадру | `["pointer", 742, 272]`. Координаты внутри `frame.png`, от верхнего левого угла. |
| Прицел в мире | `["cell", 318, 42]`. Координаты тайла, камера может следовать за героем. |
| Кнопка мыши | `["button", 1, true]` для ЛКМ, `["button", 2, true]` для ПКМ, `false` для отпускания. |
| Время на действие | `["wait", 4]` даёт четыре такта физики. Сумма всех `wait` в запросе — до 7200 тактов. |
| Выход | `["quit"]` закрывает игру без нового снимка. |

Помощник подаёт события клавиатуры и мыши через ввод Godot. Для прицела по клетке он задаёт только координату мыши через `Player.test_input["mouse"]`. Перемещение, добыча, смена времени и выдача предметов идут через игровую логику. Удержания `E`, прыжки, копка и строительство требуют тактов между нажатием и отпусканием. В конце каждой серии помощник отпускает все удерживаемые кнопки. После короткой серии проверьте кадр и показания `state.json`.

Вставьте путь, который вывела первая команда запуска, в `$artifactDir` второго терминала. Пример открывает инвентарь, проверяет кадр и затем крафтит, ставит и заправляет первую горелку.

```powershell
$artifactDir = 'АБСОЛЮТНЫЙ_ПУТЬ_ИЗ_ПЕРВОГО_ТЕРМИНАЛА'

function Wait-PlaytestState([int]$Id) {
    $statePath = Join-Path $artifactDir 'state.json'
    $deadline = (Get-Date).AddSeconds(180)
    do {
        $snapshot = $null
        if (Test-Path -LiteralPath $statePath) {
            try { $snapshot = Get-Content -LiteralPath $statePath -Raw -Encoding UTF8 | ConvertFrom-Json } catch {}
        }
        if ($null -ne $snapshot -and $null -ne $snapshot.id -and $snapshot.id -eq $Id) {
            return $snapshot
        }
        Start-Sleep -Milliseconds 100
    } while ((Get-Date) -lt $deadline)
    throw "Нет state.json с id=$Id"
}

function Send-PlaytestInput([string]$Json) {
    $request = $Json | ConvertFrom-Json
    $inputPath = Join-Path $artifactDir 'input.json'
    $temporaryPath = Join-Path $artifactDir 'input.tmp'
    [System.IO.File]::WriteAllText($temporaryPath, $Json)
    Move-Item -LiteralPath $temporaryPath -Destination $inputPath -Force
    $snapshot = Wait-PlaytestState $request.id
    if ($snapshot.error -or $snapshot.png -ne 0) {
        throw "Ошибка серии $($request.id) ($($snapshot.png)). $($snapshot.error)"
    }
    $snapshot
}

Wait-PlaytestState 0
Send-PlaytestInput '{"id":1,"actions":[["key","I",true],["wait",2],["key","I",false],["wait",2]]}'
```

Откройте `frame.png` и найдите строку **«Горелка»**. В контрольном окне 1280×720 её центр попадал в `(742,272)`. Размер интерфейса и открытые рецепты меняют положение строк. Если координаты отличаются, замените их в `pointer`.

```powershell
Send-PlaytestInput @'
{
  "id": 2,
  "actions": [
    ["pointer",742,272],["button",1,true],["wait",2],["button",1,false],["wait",2],
    ["key","I",true],["wait",2],["key","I",false],["wait",2],
    ["key","3",true],["wait",2],["key","3",false],
    ["cell",318,42],["button",2,true],["wait",4],["button",2,false],["wait",2],
    ["key","2",true],["wait",2],["key","2",false],
    ["cell",318,42],["key","E",true],["wait",4],["key","E",false],["wait",120]
  ]
}
'@
```

Рецепт стоит 4 камня и 2 хлама. В стартовом наборе камень освобождает третий слот, туда попадает горелка. Второй слот содержит уголь. После серии сообщение «Топливо загружено в горелку» и `stage=2` подтверждают первый шаг. Для кадра с лучом при необходимости дайте ещё 180 тактов отдельным запросом. Луч от угля имеет красное действие, а в палитре игры выглядит золотистым.

## Маршрут контрольного забега

1. **Лагерь.** Заправьте первую горелку. Подойдите к левому терминалу `(314,43)` и держите `E` около 2,2 с (132 такта). Прыгните влево с `A` и `Space` к сундуку `(310,43)`, откройте его и нажмите «Забрать всё». В контрольном кадре кнопка была в `(315,313)`. Убедитесь, что Радужное ядро теперь в инвентаре.
2. **Шахта.** Через ложбину двигайтесь влево к столбцу `x=287`. Копайте вниз видимую первую клетку по лучу кирки, подбирая выпавшее. Кристалл глитча был на глубинах `y=53` и `y=59`, медь в `(288,57)`, уголь попадался в области `x=283…291, y=54…57`. Для запуска нужны 12 добытых клеток руды. Камень и хлам в этот счётчик не входят. В контрольном забеге `ore=12` примерно на `1:29`.
3. **Подъём.** Со дна шахты в столбце `287` около `y=61` прыгайте и ставьте камень под ногами, когда освободится целевая клетка. От начала прыжка до первого пробного ПКМ около 17 тактов. Повторите для рядов `59, 57, 55, 53, 51, 49`, затем прыгайте вправо с `D` к лагерю. Если блок не поставился, проверьте слот, клетку и положение ног на кадре.
4. **Оптика.** Скрафтите ещё две горелки. После подбора меди строка «Горелка» сместилась в `(742,315)`. Поставьте ядро в `(320,42)`. Горелка слева `(318,42)` смотрит вправо и горит красным от угля. Поставьте правую в `(322,42)`, поверните двумя отдельными ПКМ к ядру и заправьте медной рудой для зелёного. Верхнюю поставьте в `(320,40)`, поверните одним ПКМ вниз, заправьте кристаллом глитча с `E` в прыжке. Между каждым носиком и ядром оставьте свободную клетку. Сверяйте слот с `items` при смене топлива.
5. **Дуги.** Оставьте пустой слот для переключения горелок коротким `E`. Выставляйте активные комбинации `R` → `RG` → `G` → `GB` → `B` → `BR`. Здесь `R` — красный, `G` — зелёный, `B` — синий. Ждите около двух игровых секунд между комбинациями и проверяйте, что дуга зажглась, прежде чем продолжить. Уже полученные дуги сохраняются. Все шесть были готовы к `2:03`.
6. **Первая ночь и сигнал.** Дождитесь первого рассвета около `4:00`. Перед удержанием `E` у ядра на 3 с (180 тактов) выберите **непустой слот**, например со светокристаллом. На `7af1c8c` удержание `E` пустой рукой разбирает ядро за 0,9 с и перехватывает запуск. Проверьте `relay` и `remaining`. Удержание сигнала длится 90 игровых секунд. При приближении фантомов используйте `Q` и ЛКМ по цели. Перед длинным ожиданием проверяйте HP, таймер и окрестности на кадре.
7. **Финиш.** Зафиксируйте `signal_sent=true`, `state=2` (`WON`) и видимый экран эвакуации. Для сверки с забегом сохраните копии `state.json` и `frame.png` до отправки новых команд. Время и счёт боя могут различаться из-за движения и действий игрока. Проверяемый итог — шесть дуг, выполненные условия запуска и законченный сигнал.

## Что приложить к результату

- Коммит, версию Godot, сид, способ запуска и игровое время. Запишите ключевые серии ввода или их `id`, последние `stage`, `ore`, `day`, `arcs`, `remaining`, `signal_sent`, `state`, `mined`, HP и `deaths`. Число убитых фантомов видно в статистике финала.
- Кадры первой горелки, шахты или подъёма, шести дуг, экрана эвакуации. Файлы помощника перезаписываются, поэтому снимки для отчёта копируйте сразу. Для каждого сбоя запишите последнее действие, выбранный слот и наблюдаемое сообщение или состояние. Отдельно отмечайте время до исправления и понадобилась ли подсказка.
- Отдельный прогон на физическом Android. Запишите модель, диагональ, сборку, настройки масштаба и результат проверки тачем. Проверьте тап по рецепту, выбор слота, короткий и длинный тап по постройке, подъём с прыжком и установкой блока, старт сигнала и кнопки финала. Прогон через ввод ПК подтверждает настольный маршрут. Результат Android появляется только после замера на устройстве.
